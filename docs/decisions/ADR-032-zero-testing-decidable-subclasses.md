# ADR-032 — zero-testing: no unsound test ever; sound tests over named decidable subclasses

**Status:** Proposed (2026-08-08)
**Reversibility:** **one-way.** The tier a zero-test lands in is visible in its return type
(`Proved` vs `Probable(ConditionalOn(..))` vs a structured refusal), and consumers branch on it.
**Supersedes:** ADR-017 §2's third bullet ("resolvent offers no transcendental zero-test at
any layer") and its Consequences line calling the separation permanent;
`README.md`:44-47; `DESIGN.md`:152; `ROADMAP.md`:388; `plans/roadmap.md`:298.
It supersedes **none** of ADR-017 §2's first two bullets — transcendentals still live in L4
only, and L0–L3 still never see them.
**Gates lanes:** **C1** (the M9 zero-test tier lane in `resolvent-calculus`), and every later
analytic lane whose output can be asked "is this zero". **Not X2 or X4** — a draft named those,
but `diff` and `is_polynomial_in` neither perform nor depend on a zero test, and listing a lane
in `Gates lanes:` that the ADR does not actually gate is what makes the `lanes.toml` manifest
stop meaning anything.
**Evidence:** Richardson, *Proc. Amer. Math. Soc.* / undecidability of the identity problem,
1968; Richardson, "How to recognize zero", *J. Symbolic Computation* 24(6), 1997;
Lindemann–Weierstrass; ADR-029 §1; ADR-011 §5; `CLAUDE.md` §1 (rate ceilings).

---

## Context

The founding set states the rule as an absolute:

> **No transcendental zero-test, at any layer, ever.** Undecidable in general
> (Richardson/Schanuel). (`README.md`:44)

The soundness instinct is right and the formulation refuses things that are decidable. The
concrete defect, reachable on the first day a general-purpose consumer exists:

**`sin(π/6) == 1/2` is refused.** Under ADR-017 §2, `sin` is an opaque `Apply(FuncId, …)`
node and evaluating one into an exact algebraic context returns
`Unsupported::TranscendentalSymbol`. But sine at a rational multiple of π is an *algebraic
number* — deciding it is exactly what L3 exists for, the answer is exact, and the refusal is
a false negative produced by classifying an expression by the *symbols it is written with*
rather than by the *value it denotes*.

The mathematics the absolute rule is reaching for is real but narrower than the rule:

- **Richardson (1968).** For the class generated by the rationals, π, log 2, a variable, the
  ring operations, and composition with `sin`, `exp` and `|·|`, the identity problem is
  undecidable. This is why no *general* zero-test can exist and why "best effort" is not an
  option — an intransitive equality produces a topologically inconsistent arrangement, the
  F2 failure ADR-017's Alternatives already names.
- **But undecidability is a property of that class, not of every class containing a
  transcendental symbol.** Algebraic constants: decidable, unconditionally. Exp-log
  constants: decidable *conditional on Schanuel's conjecture* (Richardson 1997) — which is
  what the established commercial systems actually run, generally without saying so.
- **Some non-vanishing results are unconditional theorems.** Lindemann–Weierstrass gives
  `e^α ≠ 0, 1` for algebraic `α ≠ 0`, and π's transcendence makes any nonzero rational
  polynomial in π nonzero. These decide *one side* exactly, with no conjecture.

The rule that survives all of this is not about transcendence. It is about **soundness**, and
about the assumption being visible in the type.

## Decision

### The rule

> **No unsound zero-test, at any layer, ever.** A sound zero-test over a *named decidable
> subclass* is permitted, and required to carry its assumption in its return type.

Four tiers, and a routine states which one it is in.

### Tier 0 — banned, permanently, at every layer

**Numeric zero-testing.** "Evaluate to `n` digits; if it looks like zero, it is zero." No
precision, no digit count, no adaptive escalation makes this sound, and it is what most CAS
equality bugs are. This is the rule the founding set was protecting and it is unchanged and
absolute. It is also the mutant every certificate in this ADR must reject.

### The signature, fixed first, because it is what makes the tiers expressible

```rust
// resolvent-calculus — a FREE FUNCTION over a borrowed Store, not a Store method.
pub fn is_zero(store: &Store, e: ExprId, tiers: &TierPolicy, budget: Budget)
    -> Result<Certified<bool>, Error>;
```

**It cannot be `Store::is_zero`.** `Store` is defined in `resolvent-expr`, and an inherent
method on it would put the tier machinery — and therefore an edge to `resolvent-real` — inside
L4, which is the exact thing §Where the tier check happens forbids. A draft of this ADR wrote
`pub fn is_zero(&self, …)` and quietly reintroduced the coupling the crate split exists to
prevent. The free-function form is also what keeps `resolvent-expr` usable by a consumer that
never links `-calculus`.

**Not `Verdict<Sign>`, and not `Verdict` at anything.** ADR-011 §5 / `API.md` INV-18 bind here:
`Verdict` is produced **only** by enclosure and filter APIs and never by an algebraic-decision
API, and a zero-test is the archetypal algebraic-decision API. A draft of this ADR returned
`Verdict::Unknown` for Tier 3 and `Verdict::Certain(NonZero)` for Tier 1(c) — the first
violates INV-18 outright and the second is not even well-typed, since `NonZero` is not a
`Sign`. `Certified<bool>` carries the answer in the value and the tier in the `Certainty`,
which is the mechanism the library already has (ADR-010 §2).

### Tier 1 — unconditionally decidable. Returns `Certainty::Proved`.

| Subclass | Mechanism |
|---|---|
| **(a) Algebraic constants** | L3's existing machinery. An algebraic number is zero iff its minimal polynomial is `x`. Already built; nothing new |
| **(b) Transcendental *symbols* at arguments that denote algebraic values** | An explicit, committed reduction table: `sin`/`cos`/`tan` at rational multiples of π, `exp(0)`, `log(1)`, `arcsin(1/2)`, and so on. Each entry reduces the node into L3 and the question becomes (a) |
| **(c) One-sided non-vanishing by a proven transcendence theorem** | Lindemann–Weierstrass and Gelfond–Schneider certify `≠ 0` for named families. Asymmetric by nature: proves non-zero, never zero — which `Certified<bool>` expresses without a special case, as `Ok(Certified { value: false, certainty: Proved })`. The asymmetry is that Tier 1(c) can *only* ever produce `false`; it never establishes zero-ness |

Tier 1(b) is the tier that fixes `sin(π/6)`, and it is a lookup table with witnesses, not a
decision procedure.

### Tier 2 — conditionally decidable. Off by default. Never `Proved`.

**Exp-log constants under Schanuel's conjecture** (Richardson's algorithm). Permitted as an
**opt-in, non-default** capability returning
`Ok(Certified { value, certainty: Probable(ProbableReason::ConditionalOn(Conjecture::Schanuel)) })`.

*This adds a variant to `ProbableReason` and a small `Conjecture` enum — both owned by
ADR-011 §3's "structured, never a string" rule, and both requiring an ADR-011 amendment in the
commit that lands them. A consumer's fail-closed path matches on the variant.*

Three constraints, and they are what make this admissible under `CLAUDE.md` §4's
"no 'probably correct' mode anywhere that is not visible in the type":

- It is **never** reachable on the default path. A caller asks for it by name.
- It **never** returns `Proved`, regardless of how confident the run was. The conjecture is
  in the answer or the answer is not returned.
- Its `Probable` rate is tracked with a committed ceiling in `sharpness-ceilings.toml`, on the
  ADR-024 ratchet, like every other non-`Proved` outcome.

### Tier 3 — everything else. A structured refusal, not a `Verdict`.

`Err(Unsupported::UndecidableZeroTest { .. })`, or `Unsupported::TranscendentalSymbol { name }`
where the question cannot be posed at all. Both are structured and matchable (ADR-011 §3).
This is the default for anything not named in Tiers 1 and 2, and it is a **refusal**, not an
indeterminate answer — the distinction matters because `is_zero` never returns a value it is
not certain of at its declared tier.

### Where the tier check happens

At the L4→L3 boundary, and only there. The evaluation path becomes: **attempt the Tier-1(b)
reduction first; if it succeeds the question is algebraic and L3 answers it; if it does not,
refuse as before.** No L0–L3 code changes, and nothing below L4 learns what a `FuncId` is.

**The tier machinery lives in `resolvent-calculus` (L5), not in `resolvent-expr` (L4)**
(ADR-005, amended 2026-08-08). A reduction that produces an `AlgebraicReal` needs
`resolvent-real`, and putting it in `resolvent-expr` would give L4 a dependency on L3 —
reinstating exactly the coupling ADR-017 §3 removed so that L4 could never hold the L3 lane
hostage. A zero-test entry point appearing in `resolvent-expr` is a layering defect and gate
L1 catches it as a new dependency edge.

### Certificates and mutants

Per `CLAUDE.md` §1, the reduction table is the new machinery and needs its own verdict:

| Certificate | Asserts |
|---|---|
| `reduction::witness_relation_holds` | Every Tier-1(b) entry ships the algebraic relation its value satisfies, and the produced `AlgebraicReal` satisfies it. `sin(π/6) → α` is accepted only if `α` satisfies the committed relation, not because the table says so |
| `reduction::agrees_with_isolation` | The reduced value's isolating interval contains the oracle's numeric evaluation of the original expression. A **cross-check**, not the verdict — it catches a wrong table entry, and per `CLAUDE.md` §1 it may not be the certificate, because it consults a numeric evaluation |
| `zero_test::tier_is_visible_in_type` | Compile-fail test: a Tier-2 path returning `Certainty::Proved` does not compile |
| `zero_test::refusal_rate_under_ceiling` | The Tier-3 refusal rate on the committed corpus is under its `sharpness-ceilings.toml` entry |

**Mutants:**

- **The numeric mutant** — a zero-test implemented as Tier 0 (evaluate to 50 digits, compare
  against a threshold). Must be rejected. This is the mutant that matters most, and the
  corpus needs at least one instance where it gives the wrong answer: a nonzero exp-log
  constant smaller than the threshold.
- **The table mutant** — `sin(π/6) → √3/2`. The real mistake, plausible, compiles, produces a
  well-formed algebraic number. Must be rejected by `witness_relation_holds`.
- **The trivial-constant mutant** — refuse always. Passes every soundness certificate in
  this ADR and is useless, which is precisely why the Tier-3 refusal-rate ceiling exists and is
  gated (`CLAUDE.md` §1, third certificate rule).

## Consequences

- **`sin(π/6) == 1/2` is answerable, exactly, with `Certainty::Proved`.** That is the point.
- **The soundness property is unchanged.** No path in any tier can return a wrong answer; the
  weakest thing any of them returns is a structured refusal, or a `Probable` carrying its
  conjecture by name.
- **`ProbableReason` gains a `ConditionalOn(Conjecture)` variant**, and `Conjecture` is a
  small enum, not a string (ADR-011 §3). A consumer's fail-closed path matches on it.
- **The reduction table is a maintenance surface and a licensing hazard.** It is exactly the
  kind of table that is easiest to transcribe from a Tier-B source. It is derived from the
  literature with a `Derivation:` line and a committed research note like everything else, and
  the note is what proves the discipline (`CLAUDE.md` §6).
- **Tier 2 will be requested as a default and must not become one.** Its whole admissibility
  rests on being opt-in. If it ships default-on, resolvent is a system whose default answers
  depend on an open conjecture without saying so — which is the thing this ADR exists to
  refuse.
- **ADR-017's "the transcendental scope decision is permanent and must be stated in the crate
  docs, because it will be repeatedly re-proposed" survives with its meaning intact.** What is
  permanent is Tier 0's ban and the visibility requirement, not the blanket refusal.

## Alternatives considered and why rejected

**Keep the absolute: no transcendental zero-test, ever.** Rejected. It refuses decidable,
exact, in-scope questions — `sin(π/6)` is the minimal example and a general-purpose consumer
hits it immediately. It classifies expressions by the symbols they are written with rather
than the values they denote, which is not a mathematical distinction.

**Allow a general "best effort" zero-test with a confidence value.** Rejected absolutely, and
this is ADR-017's original rejection restated because it is still right: best-effort
zero-testing produces an intransitive equality, a sort over it produces garbage, and a
geometry consumer produces a topologically inconsistent arrangement. Tier 0 is banned in this
ADR precisely so that widening the rule does not widen that.

**Ship Tier 2 as the default because the established systems do.** Rejected. That the
commercial systems run a Schanuel-conditional procedure without surfacing the assumption is an
argument for surfacing it, not for copying the omission.

**Fold Tier 1(b) into Tier 1(a) by requiring the caller to reduce.** Rejected. It is the same
refusal in a different place: the caller cannot reduce `sin(π/6)` without the table, so
"the caller does it" means every consumer writes the table, differently.

**Treat Tier 1(c) as out of scope because it is one-sided.** Rejected. A proof that a value is
nonzero is a complete answer to the question a sign query is actually asking, and it is
unconditional. Discarding it would mean refusing where a theorem gives a proved answer.

---

## What would reverse this

- **A tier boundary proving unmaintainable** — specifically, a reduction-table entry found to
  be wrong in released code. That is evidence `witness_relation_holds` is not strong enough,
  and the response is to strengthen the witness requirement, not to retreat to the blanket
  refusal.
- **Schanuel's conjecture being refuted.** Tier 2 is deleted and its `Probable` results become
  refusals. This is why Tier 2 may never return `Proved`: the reversal must be a deletion,
  not a correctness incident.
- **The Tier-3 refusal rate sitting at its ceiling with no path down.** That would mean the
  named-subclass approach does not cover enough of real usage to be worth its complexity, and
  the honest response is to say so and keep Tier 1 only.
